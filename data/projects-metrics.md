# 两个项目的工程指标

## ESP32 桌面智能显示终端

**项目定位**：ESP32-C3 + ST7789 TFT 多模式智能显示终端（时钟/天气/相册/股票行情）

### 核心量化指标

| 指标类别 | 指标 | 数值 | 验证方式 |
|---------|------|------|---------|
| **长期稳定性** | 12 小时零重启运行 | 731 心跳 / 0 次重启 / 0 次崩溃 | 连续监控日志 |
| | 堆内存零泄漏 | +2,632 B 净增长（正向） | 12h 趋势分析 |
| | 最大连续块稳定 | 全程恒定 124,916 B | 零碎片化证据 |
| **自愈能力** | TCP 熔断器自动恢复 | 12 次跳闸 / 12 次自愈 | 2.8h 真实环境测试 |
| | 修复前人工干预频率 | 每 14 分钟重启一次 → 零干预 | 对比测试 |
| **性能优化** | 并发请求成功率 | 42 连发全部 200（修复前第 2 发即 RST） | 压力测试 |
| | 网页响应卡顿 | 45% 占空比 → 25% 占空比 | 尾部延迟测量 |
| | 首页加载时间 | 5.2s → 2.33s（降 55%） | A/B 对比 |
| **资源占用** | Flash 占用 | 62.2% (1,305,040 / 2,097,152 字节) | 编译产物实测 |
| | 静态 RAM 占用 | 14% (46,164 / 327,680 字节) | .map 文件分析 |
| | AsyncTCP 栈余量 | 83% 空闲 (13,628 / 16,384 字节) | 运行时水位监控 |

### 关键技术突破

1. **测量—证伪—修复—复测闭环**
   - 案例：Flash 占用"95.1% → 62.2%"实为分区方案变更（分母改变），用数据否决了"必须删 TLS"的直觉方案
   - 台账文档：PERFORMANCE.md（5,049 行，防乌龙铁律 5 条）

2. **周期共振陷阱识别**
   - 发现：闸门周期 60s ÷ 轮播周期 5s = 12，12 % 4 == 0 → 永远只命中同一只股票
   - 修复：改为每股独立 TTL + 尝试即推进时间戳

3. **指标口径三次纠正**
   - `loopMs`（窗口平均）对卡顿是瞎的 → 改用 `loopPeakMs`（尾部）
   - `maxAlloc` 点采样 → 改为趋势判定
   - 用户可感指标：最坏单轮延迟（1.7~40s）vs 平均值（125ms）

## 树莓派 MQTT 智能中控

**项目定位**：端-边-云三层架构智能中控，ESP32 显示端 + 树莓派边缘计算 + 可选 AI Agent 云端接入

### 核心量化指标

| 指标类别 | 指标 | 数值 | 验证方式 |
|---------|------|------|---------|
| **服务可靠性** | 开机自启时间 | 4 服务 26s 全部就绪 | systemd 日志分析 |
| | 幂等缓存机制 | 60s 结果缓存（成功 + 失败） | 接口契约测试 |
| | 结果未知语义 | 45s 超时 → 返回"结果未知"非"失败" | 超时场景实测 |
| **架构设计** | 端-边-云降级路径 | 3 层独立失效边界 | 故障注入测试 |
| | 直连兜底成功率 | Pi 不可达时 100% 切换成功 | 断网模拟 |
| **企微集成** | 告警去重冷却 | 1 小时内不重复推送同一告警 | 涨停板实测 |
| | 指令执行成功率 | 多次切换均成功（修复前频繁 502） | 企微群实测 |
| **AI Agent 接入** | 多机器人协作拓扑 | 群 = 总线 / 一设备一机器人 / @ 即路由 | 架构设计 |
| | 自然语言理解 | LLM 理解 + 拆步 + 排时序 + 收回执 | OpenClaw 实例 |

### 关键技术突破

1. **失效边界分层设计**
   - 端（ESP32）：Hub 不可达时直连上游兜底
   - 边（树莓派）：缓存 + 告警 + 指令总线，降级落点
   - 云（AI Agent）：可选接入，不可用时本地控制仍正常

2. **企微群多机器人拓扑**
   - 架构创新：一设备一机器人，@ 结构化提及实现零串扰路由
   - 平台保证隔离 → 应用层零代码
   - LLM 机器人按需回源（读源码 + 实验验证冷却时间）

3. **60s 幂等 + 45s 结果未知**
   - 设计决策：正常路径 15s 完成，45s 表示回执不会来
   - 语义区分："结果未知"（receipt 未到）≠ "失败"（confirmed fail）
   - 冷却判定必须先于幂等、被丢弃的不登记（防重复炮）

## 跨项目共性能力

### 人机协同方法论

- **9 类失败模式分类**：从实战中归纳，覆盖性能/资源/控制流三大类别
- **外部复核机制**：6 轮收敛（18 → 9 → 7 → 4 → 4 → 2），累计 44 条缺陷逐条核实
- **防乌龙铁律**：任何静态数字必须成组记录三要素（时点 + 产物 + 分母）

### 测量驱动决策

- **先分层定位再钻层**：多异常先按机制类别分堆，避免归因混淆
- **指标必须匹配用户可感的量**：尾部延迟 vs 平均值、最大连续块 vs 瞬时采样
- **小样本结论只能当假设**：方差大的指标需要几十到上百个样本

### Git 锚点与迭代策略

- **已知良好锚点优先**：坏基线上三次优化零效果 vs 锚点上一次修一个全过
- **逐键追问 + 先问后改**：避免笼统描述导致整条诊断链跑偏
- **一轮 loop() 最多 1 次取数**：铁律写死，后续改动必须遵守
